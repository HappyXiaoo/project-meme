# 远程机器成果回收步骤

这份文档用于在 GPU 远程机器完成训练后，将代码、模型、指标和实验材料安全地带回本地电脑，并整理成最终可提交的毕业设计项目。

## 1. 回收目标

建议从远程机器带回以下内容：

- 最新代码
- 文档与实验记录
- 模型训练结果文件
- 最终模型目录或模型压缩包
- 关键截图和日志

建议区分两类内容：

- 适合放进 git 的内容
- 不适合放进 git、需要单独下载备份的内容

## 2. 哪些内容适合放进 git

建议正常提交到 git 的内容：

- 前端代码
- 后端代码
- 训练脚本
- 实验记录文档
- 测试样例文档
- 计划书
- 人工测试集
- `metrics.json`、`metadata.json` 中的重要结果摘要

## 3. 哪些内容不建议直接 git push

通常不建议直接用普通 git push 的内容：

- `BERT` 模型权重目录
- 大型 checkpoint 目录
- 大体积日志
- 临时训练缓存

原因：

- 仓库体积会明显变大
- push/pull 会变慢
- 容易导致后续管理混乱

建议做法：

- 代码走 git
- 模型和大文件单独压缩下载

## 4. 远程机器上需要确认的目录

在远程机器上，建议重点确认这些目录：

```text
/root/project-meme/
  back-end/
  front-end/
  docs/
  data/
```

重点确认这些训练产物是否存在：

```text
/root/project-meme/back-end/artifacts/
/root/project-meme/back-end/artifacts-bert-v1/
```

## 5. 先在远程机器上做整理

建议先进入项目目录：

```bash
cd /root/project-meme
```

先检查 git 状态：

```bash
git status
```

建议先看清楚哪些文件是代码改动，哪些文件是模型产物。

## 6. 模型目录压缩

如果要把模型带回本地，建议先在远程机器上压缩：

```bash
cd /root/project-meme/back-end
tar -czf artifacts-bert-v1.tar.gz artifacts-bert-v1
```

如果还想保留传统模型产物，也可以一起压缩：

```bash
tar -czf artifacts-traditional.tar.gz artifacts artifacts-baseline
```

压缩后建议先确认文件存在：

```bash
ls -lh *.tar.gz
```

## 7. 推荐回收内容清单

建议至少带回这些内容：

### 7.1 代码与文档

- `back-end/`
- `front-end/`
- `docs/`
- `data/manual_test_set.csv`
- `计划书.md`

### 7.2 结果文件

- `back-end/artifacts/metrics.json`
- `back-end/artifacts/metadata.json`
- `back-end/artifacts-bert-v1/metrics.json`
- `back-end/artifacts-bert-v1/metadata.json`

### 7.3 模型文件

- `back-end/artifacts-bert-v1.tar.gz`

### 7.4 可选文件

- 训练日志
- 对比结果 CSV
- 页面截图

## 8. 两种回收方式

### 方式 A：代码走 git，模型单独下载

这是最推荐的方式。

步骤：

1. 在远程机器提交代码和文档改动
2. push 到 git 仓库
3. 模型目录压缩
4. 单独下载模型压缩包

优点：

- 仓库干净
- 代码和模型分离清晰
- 后续更容易维护

### 方式 B：全部打包后手动下载

如果你不想折腾 git，也可以把整个项目目录打包后下载。

例如：

```bash
cd /root
tar -czf project-meme-full-backup.tar.gz project-meme
```

这种方式最省事，但缺点是：

- 压缩包会很大
- 不利于后续持续管理

## 9. 推荐的 git 提交流程

如果代码和文档已经修改完成，建议这样做：

```bash
cd /root/project-meme
git status
git add .
git commit -m "Update experiment records and BERT workflow"
git push
```

注意：

- 如果 `.gitignore` 已经正确忽略模型目录，`git add .` 不会把模型权重带进去
- 提交前先看一眼 `git status`，确认没有把大模型目录误加进去

## 10. 模型压缩包下载建议

远程机器压缩完成后，你可以通过平台的文件下载功能或终端文件传输功能把压缩包带回本地。

建议优先下载：

- `artifacts-bert-v1.tar.gz`

如果空间允许，也可以一并下载：

- `artifacts-traditional.tar.gz`

## 11. 本地如何整理最终提交版

建议在本地整理两份内容：

### 11.1 开发仓库版

这一份用于继续维护和 git 管理，建议：

- 不包含大模型目录
- 只保留代码、文档、测试集、说明文件

### 11.2 最终提交版

这一份用于学校最终提交，建议：

- 包含代码
- 包含文档
- 包含必要模型文件
- 包含运行说明

可以在本地新建一个目录，例如：

```text
project-meme-final-submit/
```

然后把需要的模型压缩包解压进去。

## 12. 最终提交版建议包含的内容

建议至少包含：

- `front-end/`
- `back-end/`
- `docs/`
- `data/`
- `计划书.md`
- 模型运行说明
- 必要的模型目录或模型压缩包

## 13. 回收后建议立刻做的事

成果带回本地后，建议立刻做：

1. 检查本地项目是否能正常打开
2. 检查文档是否完整
3. 检查 `metrics.json` 和 `metadata.json` 是否齐全
4. 检查模型压缩包是否损坏
5. 备份一份最终提交版目录

## 14. 最稳妥的一句话方案

当前项目最推荐的回收方式是：

1. 远程机器上 `git push` 代码和文档
2. 远程机器上压缩 BERT 模型目录
3. 单独下载模型压缩包到本地
4. 本地整理最终提交版项目目录
